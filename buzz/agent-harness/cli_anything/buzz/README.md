# CLI-Anything Buzz

A stateful, secret-safe CLI-Anything harness over Buzz's real native Rust CLI.
It exposes both one-shot commands and a default REPL while leaving relay, Nostr,
persona, and validation semantics in Buzz.

## Requirements

- Python 3.10+
- The native `buzz` executable from [block/buzz](https://github.com/block/buzz)
- `BUZZ_PRIVATE_KEY` for relay commands
- Optional `BUZZ_AUTH_TAG` for owner-attested operations

Install the native backend from a Buzz checkout:

```bash
git clone https://github.com/block/buzz.git
cd buzz
cargo install --path crates/buzz-cli
```

Install this harness:

```bash
cd buzz/agent-harness
python -m pip install -e .
```

Verify both layers:

```bash
buzz --help
cli-anything-buzz backend status --json
```

## Usage

Wrapper options go before the native domain:

```bash
# Default REPL
cli-anything-buzz

# Inspect backend and command coverage
cli-anything-buzz --json backend status
cli-anything-buzz --json backend commands

# Save non-secret local preferences
cli-anything-buzz --json session set-relay https://relay.example.com
cli-anything-buzz --json session set-format compact
cli-anything-buzz --json session status

# Native Buzz reads and writes
export BUZZ_PRIVATE_KEY='nsec1...'
cli-anything-buzz --json channels list
cli-anything-buzz --json messages get --channel UUID --limit 20
cli-anything-buzz messages send --channel UUID --content -

# Desktop-managed agents do not require BUZZ_PRIVATE_KEY
cli-anything-buzz --json agents managed status
cli-anything-buzz --json agents managed list

# First invocation returns a no-op approval plan
cli-anything-buzz --json agents managed create \
  --name Docs-Codex --agent-command codex \
  --system-prompt "Work in the docs repository"

# Rerun the reviewed command to execute it in Buzz Desktop
cli-anything-buzz --json agents managed create \
  --name Docs-Codex --agent-command codex \
  --system-prompt "Work in the docs repository" \
  --start --approve

# Provision a complete channel and agent roster. Omit --approve first.
cli-anything-buzz --json agents managed provision-channel \
  --name dokploy \
  --context ~/code/greymatter/greymatter/dokploy \
  --agent Dokploy-Codex=codex \
  --agent Dokploy-Claude=claude

# Review a remote mutation without starting Buzz
cli-anything-buzz --dry-run --json \
  messages send --channel UUID --content "Hello"

# Local persona-pack operations need no relay or key
cli-anything-buzz --json pack validate ./my-pack
cli-anything-buzz --json pack inspect ./my-pack

# Native help is forwarded at any depth
cli-anything-buzz messages --help
cli-anything-buzz backend help messages send
```

All native domains are exposed: `agents`, `messages`, `channels`, `canvas`,
`reactions`, `emoji`, `dms`, `users`, `workflows`, `feed`, `social`, `notes`,
`repos`, `patches`, `issues`, `pr`, `media`, `upload`, `mem`, `pack`, and
`moderation`. `raw` forwards future native groups before the wrapper is updated.

## Credentials

The wrapper deliberately has no private-key or auth-tag option. Use:

```bash
export BUZZ_PRIVATE_KEY='nsec1...'
export BUZZ_AUTH_TAG='[...]'  # only when required
```

Forwarded `--private-key` and `--auth-tag` arguments are rejected so credentials
do not land in shell history, process listings, dry-run plans, or session JSON.
The session stores only relay URL, native output format, and reversible snapshots
of those two values.

The Desktop control descriptor is generated by Buzz Desktop in its app-data
directory with owner-only permissions. It contains a random loopback bearer
token, not a Nostr or managed-agent private key. Use
`BUZZ_DESKTOP_CONTROL_FILE` only to target an alternate/dev Desktop descriptor.

## JSON and Exit Codes

`--json` wraps native output with the command, backend, exit code, and parsed
data/error. The command is always redacted. Without `--json`, native JSON is
pretty-printed and native text is passed through.

Buzz's native exit codes are preserved:

- `0`: success
- `1`: input error or not found
- `2`: network or relay error
- `3`: authentication error
- `4`: other backend error
- `5`: write conflict

Wrapper validation errors use exit `1`, including Click option/argument errors.
Native invocations time out after 60 seconds by default and return wrapper exit
`4`; override the bound with `--timeout SECONDS` or
`CLI_ANYTHING_BUZZ_TIMEOUT`.

## Sessions

The default path is `~/.cli-anything-buzz/session.json`. Override it with
`--session` or `CLI_ANYTHING_BUZZ_SESSION`.

```bash
cli-anything-buzz session undo
cli-anything-buzz session redo
cli-anything-buzz session reset
cli-anything-buzz session path
```

Undo and redo affect local preferences only. Remote Buzz mutations are never
claimed to be reversible. History and redo stacks retain the latest 100
snapshots. Session updates are locked as one read-modify-write transaction so
concurrent wrapper processes do not overwrite one another.

## Tests

```bash
cd buzz/agent-harness
python -m pytest cli_anything/buzz/tests/test_core.py -v
CLI_ANYTHING_FORCE_INSTALLED=1 \
  python -m pytest cli_anything/buzz/tests -v -s --tb=no
```

The E2E suite requires the real `buzz` backend. It uses synthetic local persona
packs and performs no live relay mutation.

## Backend Limitation

The harness intentionally does not add a preview-bundle surface. Buzz state is
already available through structured native reads and persona-pack inspection;
the desktop app remains the visual client.
